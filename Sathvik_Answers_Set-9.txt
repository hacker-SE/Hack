J. HEALTH-CHECK FAILURE - HOW TO FIND AND FIX ROOT CAUSE
--------------------------------------------------------
1. List pods and identify failing pods:
       kubectl get pods -o wide

2. Inspect a failing pod:
       kubectl describe pod POD_NAME

3. Read container logs:
       kubectl logs POD_NAME
   If the pod has multiple containers:
       kubectl logs POD_NAME -c CONTAINER_NAME

4. Check recent events:
       kubectl get events --sort-by=.metadata.creationTimestamp

5. Check deployment and replica status:
       kubectl describe deployment nginx-deployment
       kubectl rollout status deployment/nginx-deployment

Common causes and fixes:
- Wrong liveness/readiness probe path or port:
  Set the correct HTTP path and container port.
- Application starts slowly:
  Increase initialDelaySeconds or use a startupProbe.
- Image cannot be downloaded:
  Check image name/tag and registry credentials; inspect ImagePullBackOff.
- Container exits:
  Read logs; fix application configuration or missing environment variables.
- Insufficient CPU/memory:
  Inspect describe output and resource usage; adjust requests/limits.
- Wrong service selector:
  Compare service selector with pod labels:
      kubectl get service nginx-service -o yaml
      kubectl get pods --show-labels

Example HTTP probes for an Nginx container (port 80):
    readinessProbe:
      httpGet:
        path: /
        port: 80
      initialDelaySeconds: 5
      periodSeconds: 5
    livenessProbe:
      httpGet:
        path: /
        port: 80
      initialDelaySeconds: 10
      periodSeconds: 10

These probe fields belong under the container in the Deployment YAML.
After changing the YAML, apply it:
    kubectl apply -f nginx-deployment.yaml

D. HOST AND SERVICE STATUS
--------------------------
In the Nagios web interface:
1. Open Hosts.
2. Select localhost (if configured by the image).
3. Open Services.
4. Inspect service checks and their status.

Status meanings:
- UP: Host is reachable.
- DOWN: Host check failed.
- UNREACHABLE: Nagios cannot reach the host, often because a parent
  host/network path is unavailable.
- OK: Service check succeeded.
- WARNING: Service is working but outside its warning threshold.
- CRITICAL: Service check failed or crossed its critical threshold.
- UNKNOWN: Check could not determine a valid status, often due to
  plugin, command, or configuration problems.
- PENDING: A check has not run yet.

E. TROUBLESHOOT: "UNABLE TO CONNECT TO NAGIOS PROCESS"
-----------------------------------------------------
This generally means the web interface cannot communicate with the
Nagios Core process or its command/status files.

Run on Windows CMD:
    docker ps -a
    docker logs nagios
    docker restart nagios

If it still fails:
    docker exec -it nagios bash

Inside the container:
    ps aux | grep nagios
    find / -name nagios.cfg 2>/dev/null
    find / -name nagios.cmd 2>/dev/null

Then inspect the paths returned by find and verify:
- Nagios Core process is running.
- Nagios configuration has no syntax errors.
- Nagios status and command files exist.
- Web-server/Nagios permissions allow the web interface to read status
  and write external commands.
- Disk space is available.

If the image provides a Nagios binary, test configuration using the
path found inside the container, for example:
    nagios -v /opt/nagios/etc/nagios.cfg

The exact path can differ by image version. Use the path returned by
find rather than assuming it.

After correcting the problem, restart:
    docker restart nagios

1. Confirm the host definition file is in the directory included by
   nagios.cfg.
2. Confirm the host definition has a unique host_name.
3. Confirm the host has a valid use/template and check_command.
4. Confirm the host definition file is included using cfg_file or
   cfg_dir in nagios.cfg.
5. Run Nagios configuration validation:
       nagios -v /PATH/TO/nagios.cfg
   Replace the path with the actual path found in the container.
6. Fix every configuration error.
7. Reload/restart Nagios:
       docker restart nagios
8. Refresh the web interface and check Hosts.

Example host definition (Nagios object configuration syntax):
    define host {
        use                     linux-server
        host_name               lab-ubuntu
        alias                   Lab Ubuntu Server
        address                 192.168.1.100

        host_name               lab-ubuntu

        check_command           check_ping!100.0,20%!500.0,60%

Do not paste them into CMD.

J. AUTOMATICALLY RUN COMMANDS DURING EC2 INSTANCE SETUP/STARTUP
---------------------------------------------------------------
The EC2 feature used to run commands during initial instance launch
is EC2 User Data (cloud-init on Ubuntu).

AWS Console:
1. Launch instance.
2. Expand Advanced details.
3. Enter commands in User data.
4. Launch the instance.

Example Ubuntu User Data script to create a simple web page and
install/start Apache:

    #!/bin/bash
    apt-get update -y
    apt-get install -y apache2
    systemctl enable apache2
    systemctl start apache2
    echo '<h1>BookBank EC2 Server</h1>' > /var/www/html/index.html

Allow inbound TCP port 80 in the EC2 security group to access it:
    http://YOUR_EC2_PUBLIC_IP

Important distinction:
- User Data normally runs on the first boot by default.
- If the question specifically requires a command every time the
  instance restarts, configure a systemd service or cloud-init
  per-boot script. User Data alone is not automatically rerun on
  every reboot by default.

Example systemd service for a script:
1. Create the script:
       sudo nano /usr/local/bin/start-lab-web.sh

2. Put this content in the file:
       #!/bin/bash
       systemctl start apache2

3. Save and exit, then:
       sudo chmod +x /usr/local/bin/start-lab-web.sh

4. Create service:
       sudo nano /etc/systemd/system/start-lab-web.service

5. Put this content in the file:
       [Unit]
       Description=Start lab web server at boot
       After=network.target

       [Service]
       Type=oneshot
       ExecStart=/usr/local/bin/start-lab-web.sh
       RemainAfterExit=yes

       [Install]
       WantedBy=multi-user.target

6. Enable:
       sudo systemctl daemon-reload
       sudo systemctl enable start-lab-web.service
       sudo systemctl start start-lab-web.service
       sudo systemctl status start-lab-web.service
