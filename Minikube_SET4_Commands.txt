MINIKUBE + KUBERNETES LAB COMMANDS SET-4 – Q3 (Hospital Management
System)

IMPORTANT - Run these commands in a terminal where Minikube, kubectl,
and Docker are installed. - These examples use the nginx image as a
simple test application. - Replace POD_NAME with the actual pod name
shown by kubectl get pods. - Keep the same deployment name: hospital.

============================================================ 1. START
AND CHECK MINIKUBE
============================================================

minikube start minikube status kubectl get nodes minikube dashboard

============================================================ 2. Q3(a) –
CREATE A DEPLOYMENT
============================================================

kubectl create deployment hospital –image=nginx kubectl get deployments
kubectl get pods kubectl describe deployment hospital

Expected: The hospital deployment should become available and its pod
should show STATUS Running.

============================================================ 3. Q3(b) –
SCALE TO FOUR REPLICAS
============================================================

kubectl scale deployment hospital –replicas=4 kubectl get deployments
kubectl get pods kubectl get pods -o wide

Expected: The deployment should show READY 4/4 and four pods should be
Running.

============================================================ 4. Q3(c) –
EXPOSE THE APPLICATION USING NODEPORT
============================================================

kubectl expose deployment hospital –type=NodePort –port=80 kubectl get
services kubectl describe service hospital minikube service hospital

Expected: A browser window should open and display the Nginx welcome
page.

Alternative: Get the service URL without opening the browser:

minikube service hospital –url

============================================================ 5. Q3(e) –
TROUBLESHOOT A POD
============================================================

kubectl get pods kubectl describe pod POD_NAME kubectl logs POD_NAME
kubectl logs POD_NAME –previous kubectl get events kubectl get
deployments kubectl get services

If a pod is unhealthy, inspect the Events and logs first. Fix the actual
cause (for example, an incorrect image name, application error, or
resource limit). Do not delete a pod before checking why it failed.

If you need to restart all pods managed by the deployment after fixing
the cause:

kubectl rollout restart deployment hospital kubectl rollout status
deployment hospital kubectl get pods

If the deployment uses an incorrect image, update it (replace IMAGE_NAME
with a valid image):

kubectl set image deployment/hospital nginx=IMAGE_NAME kubectl rollout
status deployment hospital

============================================================ 6. USE A
YAML FILE INSTEAD OF THE CREATE COMMAND
============================================================

Create a file named hospital-deployment.yaml with this content:

apiVersion: apps/v1 kind: Deployment metadata: name: hospital spec:
replicas: 4 selector: matchLabels: app: hospital template: metadata:
labels: app: hospital spec: containers: - name: nginx image: nginx
ports: - containerPort: 80

Apply and verify:

kubectl apply -f hospital-deployment.yaml kubectl get deployments
kubectl get pods

To expose the deployment using a separate YAML file, create
hospital-service.yaml:

apiVersion: v1 kind: Service metadata: name: hospital spec: type:
NodePort selector: app: hospital ports: - port: 80 targetPort: 80
protocol: TCP

Apply and verify:

kubectl apply -f hospital-service.yaml kubectl get services minikube
service hospital

NOTE: If you already created the deployment or service using
kubectl create / kubectl expose, do not create a duplicate with a
different name. You can use kubectl apply to manage the resources
described in the YAML files.

============================================================ 7. USEFUL
INSPECTION COMMANDS
============================================================

kubectl get all kubectl get pods -o wide kubectl get deployments kubectl
get services kubectl describe deployment hospital kubectl describe
service hospital kubectl get events –sort-by=.metadata.creationTimestamp

============================================================ 8. CLEANUP
AFTER THE PRACTICAL
============================================================

kubectl delete service hospital kubectl delete deployment hospital

If you created resources from both YAML files, you can instead run:

kubectl delete -f hospital-service.yaml kubectl delete -f
hospital-deployment.yaml

Stop Minikube:

minikube stop

Delete the local Minikube cluster only if you no longer need it:

minikube delete

============================================================ 9. QUICK
REVISION – MOST IMPORTANT COMMANDS
============================================================

minikube start minikube status kubectl get nodes kubectl create
deployment hospital –image=nginx kubectl get pods kubectl scale
deployment hospital –replicas=4 kubectl get deployments kubectl expose
deployment hospital –type=NodePort –port=80 kubectl get services
minikube service hospital kubectl describe pod POD_NAME kubectl logs
POD_NAME kubectl get events kubectl delete deployment hospital
